## Verification method

`scripts/check-name-workspace-preview.mjs` is explicitly opt-in. It requires a clean, exact source SHA, the linked Sajda Vercel project, fresh development OIDC access, the exact protected Preview origin, and independently reviewed Preview/Production Neon manifests. A wrong/missing target stops before account allocation.

The intended deployed story is compiled login → two explicit domain checks → save one private brand configuration → actual API/Neon confirmation → reload → duplicate retry and stale-version rejection → second-owner isolation → reopen without automatic provider activity → explicit recheck. It allocates only two new UUID-bound `example.test` accounts and captures verification mail locally. It does not prove deployed signup, inbox delivery, paid entitlements, social-provider login or physical iPhone/VoiceOver behavior.

The search fence allows no more than two requests, each for the same two exact `.com`/`.ai` names. No generated names, AI consent, social checks or payment calls are permitted. Credentials, cookies and protection headers remain in memory, not command arguments or screenshots. Fixture accounts/projects and exact fixture-only rate buckets must be reconciled and removed before a successful receipt.

The workspace cleanup independently binds the run UUID to its two exact emails and any acknowledged SDK IDs. A lost delete acknowledgement is reread, with no more than two exact attempts. Both owners are attempted after transient failure; already-absent known users still have children and fixture-only hashes checked. Failures include a non-secret run ID for recovery, suppress raw database errors and never claim successful cleanup. The older auth lifecycle runner was not retrofitted with this helper in this increment; do not reuse it for a new destructive cleanup run until the same lost-ACK review is applied.

Local responsive fixtures remain synthetic UI evidence. Their mock responses are not evidence of deployment, real registry answers, billing or persistence. The workspace probe separately checks rendered package/index presence, not a pixel-by-pixel comparison of every displayed timestamp.
