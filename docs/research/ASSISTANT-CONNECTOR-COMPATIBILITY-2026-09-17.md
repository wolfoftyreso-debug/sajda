## Packaging and public distribution

OpenAI's current portable package uses root `plugin.json`, root `mcp.json`, and optional `skills/`. The MCP file declares the Agent Plugins schema and a `type: "streamable-http"` server. `.codex-plugin/plugin.json` and `.mcp.json` remain supported compatibility packaging. Registered connection IDs beginning `plugin_asdk_app...` are obtained from actual developer-mode registration; they cannot be invented. Local marketplace installation is an authoring/testing route whose availability varies by surface, not automatic public publication. [OpenAI packaging](https://developers.openai.com/plugins/build/plugins).

OpenAI public submission requires a verified developer/business identity and Apps Management write access. Prepare listing information, public endpoint and domain verification access, tool annotations, policy URLs, starter prompts, and positive/negative test cases. Review and publication remain external launch steps. [OpenAI submission](https://developers.openai.com/plugins/deploy/submission).

Claude remote connectors are installed by URL; `.mcpb` is a separate bundle format for local Desktop extensions. Directory inclusion requires submission and review. Current remote submission documentation requires a Team/Enterprise organization and directory-management access. An MCP endpoint functioning privately does not imply directory approval. [Claude submission](https://claude.com/docs/connectors/building/submission), [Desktop bundles](https://claude.com/docs/connectors/building/mcpb).

Grok's reviewed documentation establishes a custom URL install route and a connector catalog. It does not establish a self-service third-party catalog submission procedure. Treat catalog listing requirements as unknown until separately verified. [Grok connectors](https://docs.x.ai/grok/connectors).

## What “recognizes a business idea” can mean

The host assistant selects enabled tools from metadata and the current conversation. Good tool descriptions can support indirect intent, but they do not guarantee invocation. OpenAI explicitly recommends testing direct, indirect and negative prompts. Claude's documented API behavior similarly distinguishes a request that maps to a tool capability from general knowledge about the topic. Grok describes on-demand calls during conversations. [OpenAI metadata guidance](https://developers.openai.com/plugins/guides/optimize-metadata), [Claude API tool selection](https://platform.claude.com/docs/en/agents-and-tools/mcp-connector), [Grok on-demand calls](https://docs.x.ai/grok/connectors/custom-mcp-tunneling).

Engineering inference: these integrations should be treated as host-invoked tools, not passive access to all chats or a background subscription to chat transcripts. No such universal chat-reading or server-initiated suggestion channel was established by the reviewed sources. A connector may inspect only context the host actually sends it. Enabling a connector does not by itself guarantee that the host loads a companion skill or that a skill fires for every message.

## Recommendations for Sajda

1. Maintain one public HTTPS Streamable HTTP MCP service with typed tools, accurate annotations, useful errors, and a concise model-readable result. Keep host install instructions separate because consumer UIs, CLI files, and API request formats differ.
2. Put business-idea recognition and timing guidance in the host's skill/instructions where supported: detect a concrete new venture with sufficient context and a naming need; avoid interruptions during unrelated work, discussion of existing companies, quotations, or after refusal. Ask: “Vill du att Sajda tar fram topp 10 företagsnamn för din idé?”
3. Preserve a distinct consent step before name generation. Send a short approved business brief rather than an entire transcript. Connection authentication, host tool approval, and consent to generate names are different states. xAI API cannot supply the OpenAI `require_approval` mechanism; any application-owned xAI integration needs its own user-confirmation state before enabling/calling generation.
4. Make any assessment tool advisory: it can recommend offering the service only after a host invokes it. An MCP tool cannot make itself run on every chat message. Label that boundary accurately in product copy.
5. Return ranked Top 10 candidates with short rationale and explicit check status. Do not label names, domains, or trademarks “available” unless an actual relevant check succeeded; unsupported checks should remain unverified.
6. Verify the same scenario set separately in ChatGPT, Claude, Grok, and each builder: business-idea discussion produces an offer; accepting produces names; declining suppresses repeat offers; unrelated discussion stays quiet; explicit naming requests work; unavailable backend gives an honest recoverable result. Record host/version/date, tool call and observed behavior.

Release terminology should distinguish **implemented**, **protocol-tested**, **connected in host**, **scenario-tested**, and **publicly listed**. This research establishes documented provider routes only.
